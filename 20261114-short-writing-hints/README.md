# 短い指示で Claude の日本語は変わるか

Claude が書く日本語の言い回しは、プロンプトに一言添えるだけで改善するという意見がある。次の 2 つの指示を Claude に渡し、指示がない場合と比べた。

- [「和語を使うな、熟語とカタカナ語で説明しろ」](https://x.com/odashi_t/status/2121040960767590881): 独特の言い回しが体感で 6 割ほど減るという
- [「助詞・助動詞・接続詞の使い方を見直して」](https://x.com/sub_827/status/2119493058526085471): これだけで文章の訂正ができあがるという

生成した 18 本の本文は、ページ (`site/index.html`) で条件名を隠して並べて読み、気になる表現にマークを付けて比べられる。形態素解析で求めた文体の指標も、参考としてページに載せている。

## 実験の設計

イベントソーシングを解説する、見出しで構造化した Markdown の文書を書かせた。共通のプロンプトは次のとおりで、指示ありの条件では末尾に空行と指示文を足した。

```
「イベントソーシング」について、ソフトウェアエンジニア向けの解説ドキュメントを Markdown で書いてください。見出しで 4〜6 節に分け、全体で 2500〜3500 字程度にしてください。
```

| 項目 | 値 |
| --- | --- |
| モデル | Opus 5.5、Sonnet 5.5 (どちらも effort: medium) |
| 概念 | イベントソーシング |
| 条件 | 指示なし、和語禁止、助詞見直し |
| 試行 | 条件ごとに 3 回 (2 モデル × 3 条件 × 3 回 = 18 本) |

各試行は `claude -p` を 1 回ずつ実行して生成した (`generate.mjs`)。実行者の Claude Code の設定が本文に影響しないよう、空の一時ディレクトリで、次のフラグを付けて実行している。

| フラグ | 外すもの |
| --- | --- |
| `--setting-sources ""` | ユーザーとプロジェクトの設定 (CLAUDE.md、プラグイン、フック) |
| `--strict-mcp-config` | MCP サーバー |
| `--disable-slash-commands`、`--tools ""` | スキルとツール |
| `--system-prompt ""` | Claude Code の既定のシステムプロンプト |

ユーザーの CLAUDE.md にだけ書いてある規則 (Python では uv を使う) を尋ね、フラグなしでは答え、フラグありでは「なし」と答えることを確かめた。管理者が配布するプラグインはこのフラグでは外れない。

### サブエージェントで生成しなかった理由

最初は Claude Code のサブエージェントで生成していたが、サブエージェントは親のセッションの CLAUDE.md、スキル、プラグインを引き継ぐ。実際、サブエージェントで生成した Opus の指示なしの文書 3 本は、括弧をすべて半角で書いていた (半角 42、全角 0)。同じプロンプトを上の方法で生成すると、全角 39、半角 14 になった。実行者の CLAUDE.md にある「英数字やカッコ、記号は半角で入力する」の規則が効いていたと考えられる。このため、サブエージェントでの結果は捨てて作り直した。

それ以前には、3 概念について 3〜4 段落の短い説明もサブエージェントで書かせたが、指示なしでも読んで違和感のある箇所が少なく、比べる材料にならなかった。今回の文書の形式と長さは、その結果を受けて決めた。

## 本文を読んで比べる

文章の良し悪しは、本文を読んで判断する。ページでは条件名を隠して 3 条件の本文を並べて読み、気になった表現にマークを付けて、条件ごとのマークの数を比べられる。手順は次のとおり。

1. 「条件を隠して読む」にチェックを入れ、モデルと試行を選ぶ。条件を隠している間は、表示する本文を変えるたびにカードの並び順を引き直す
2. 本文を読み、気になる表現を選択して「マーク」を押す。選択は見出し、段落、箇条書きの 1 項目、引用のどれか 1 つの中に限る。コードと表にはマークを付けられない。付けたマークはクリックすると外せる
3. 読み終えたカードの「読んだ」にチェックを入れる。マークを付けたカードには自動でチェックが入る
4. 「マークした表現」の表で、モデルと条件ごとに、読んだ本数、マーク数、読んだ本文 1000 字あたりのマーク数、マークした表現の一覧を見る。この表は条件を隠している間は表示しない
5. 記録はブラウザの localStorage にだけ残るので、「書き出す」で `marks.json` に保存する。「読み込む」で書き出したファイルから記録を戻せる

マークは `{model}/{concept}/{condition}/{n}` のキー、ブロックの番号、ブロック内の開始位置と終了位置、選択した文字列で記録する。`make analyze` で本文を作り直すと位置がずれるので、マークは同じ `site/data.js` に対してだけ使える。

## 文体の指標 (参考)

指標は形態素解析で数えた文体の特徴で、文章の良し悪しは表さない。指示で語の選び方、文の長さ、文体、文書の構造がどう動いたかを見る参考として求めた。

`analyze.py` は本文を Markdown のブロック (見出し、段落、箇条書きの項目、引用、コード、表) に分け、地の文 (段落、箇条書きの項目、引用) を fugashi と unidic-lite で形態素解析する。見出し、コード、表は語や文の指標に含めない。

- **語種の割合**: UniDic の語種 (和語、漢語、外来語、混種語) の割合。助詞、助動詞、記号を除いた語を母数にする
- **1 文の平均文字数**: 段落と引用を句点で区切った文の、空白を除いた文字数の平均。箇条書きの項目は文として数えない
- **1 文あたりの助詞・助動詞・接続詞**: 段落と引用の中の、品詞ごとの出現数を文の数で割った値
- **です・ます調の文の割合**: 文末が「です」「ます」「ました」などで終わる文の割合
- **硬い漢語述語**: 「〜可能である」「〜困難」「〜に該当」「〜が存在」「〜が発生」「〜を実施」「〜を実現」の 1000 字あたりの出現数。この語の一覧は、段落の説明を和語禁止で書かせた出力を読んで選んだので、和語禁止の変化を検出しやすい方向に偏っている
- **構造**: 見出しの数、箇条書きの項目数、地の文に占める箇条書きの文字数の割合、1000 字あたりの太字の数、コードブロックの数、表の数

## 未検証のメモ

指示なしの文書も、読んで違和感のある箇所は多くなかった。理由として次の 2 つを考えているが、どちらも確かめていない。

- 各試行は空のコンテキストから 1 回で書かせている。違和感のある文章は、作業でセッションが長くなった後に文書を書かせたときに出やすいのかもしれない。確かめるには、コードの調査や修正などのやり取りを一定量重ねたセッションの最後に、同じプロンプトで文書を書かせて比べる
- 概念を解説する説明文は、Claude が得意な種類の文章だという見方もある。作業の報告、設計の判断の記録、PR の説明など、別の種類の文章では結果が違うかもしれない

## 限界

- 概念は 1 つ、各条件は 1 モデルあたり 3 本で、統計的な検定はしていない
- 指標は文体の特徴を測るもので、文章の質や読みやすさを直接は測っていない。質の比較は、ページで条件を隠して読むことで補う。ただし、です・ます調かどうかなど、文体の違いで条件を見分けられてしまう場合がある
- 内容の正確さは確認していない
- `claude -p` は Claude Code を経由するので、API に同じプロンプトを直接渡した結果とは異なりうる。システムプロンプトを空にしても、作業ディレクトリや OS などの環境情報は渡され、管理者が配布するプラグインも外れない。プロンプトは 100 トークン前後だが、入力は 1 回あたり約 650 トークンだった
- unidic-lite は古い版の UniDic を使う。「保存する」の「する」のようなサ変動詞の語尾も和語に数えるため、漢語の多い文章でも和語の割合が 0 にはならない

## ファイル

| パス | 内容 |
| --- | --- |
| `experiment.json` | プロンプト、モデル、概念、条件の定義 |
| `prompts.mjs` | `experiment.json` から全試行のプロンプトを組み立て、`runs/prompts.jsonl` に書き出す |
| `generate.mjs` | 出力がまだない試行を `claude -p` で生成する |
| `runs/prompts.jsonl` | 試行ごとのプロンプトと出力先 |
| `runs/{model}/{concept}/{condition}-{n}.md` | 生成された本文 |
| `runs/{model}/{concept}/{condition}-{n}.json` | `claude -p` の出力から抜き出した、使ったモデル、所要時間、トークン数 |
| `analyze.py` | 本文を解析し、指標とトークン列を `site/data.js` に書き出す |
| `site/` | 比較ページ |

## 実行方法

```sh
make prompts    # runs/prompts.jsonl を作る
make generate   # claude -p で本文を生成する (Claude Code にログインしておく。同時実行数は CONCURRENCY で変えられる)
make analyze    # runs/ を解析して site/data.js を作る
make serve      # http://localhost:8765/ でページを確認する
```
