# Review Entry

未コミットの変更があるエントリ (`yyyymmdd-slug/`) を、コミット前に検査する。
`check.mjs` と gitleaks はコミット時に pre-commit hook が実行するので、この skill では実行しない。
この skill はコミットしない。問題がなければ最後に `/commit` を提案する。

<ARGUMENTS>
$ARGUMENTS
</ARGUMENTS>

## 1. 対象を決める

引数でディレクトリが指定されていればそれを対象にする。
指定がなければ `git status --porcelain` から、変更のあるトップレベルのエントリをすべて対象にする。
対象がなければ、そう伝えて終了する。

## 2. Vite のビルド

対象に `vite.config.*` があり、`site/` 以外のソースに変更がある場合は、そのディレクトリで `npx vite build` を実行する。
ビルド結果の `site/` も変更に含まれることを伝える。

## 3. 目視の検査

対象の差分を読み、次を確かめる。

- `site/` のページが、サブディレクトリ (`https://pokutuna.github.io/scratch/<entry>/`) に置かれても動く相対パスで参照している
- 画像は 1 か所にだけ置かれ、README とページの両方がそれを相対パスで参照している
- ビルド結果 (`site/assets/*.js` など) に API キー、トークン、個人情報、ローカルの絶対パス (`/Users/...`) が埋め込まれていない
- コード、サンプルデータ、画像に、仕事に関する情報 (勤務先の名前、社内の URL やホスト名、業務のデータ) が含まれていない。スクリーンショットは写り込みも確かめる
- `node_modules/` や大きなバイナリなど、コミットすべきでないファイルが含まれていない

## 4. Codex レビュー

`--no-codex` が指定されていなければ、Skill ツールで codex plugin の `codex:codex-review` を次の引数で起動する。plugin が入っていなければ、この手順を飛ばしたことを報告に含める。

```
-y 未コミットの変更のうち <対象エントリ> 以下をレビューしてください。観点: 公開リポジトリに置いてよい内容か (secret、個人情報、仕事に関する情報)、GitHub Pages のサブディレクトリで動くか、コードの明らかな誤り
```

レビューには数十分かかることがある。結果は Codex のものとして、優先度やタイトルを変えずに伝える。

## 5. 報告

手順 2〜4 の結果をまとめ、修正が必要な点と、問題がなければ `/commit` でコミットできることを伝える。
